# Аналитика онлайн кинотеатра по подписке

Целиком построен на синтетических данных: небольшой симулятор создает мир онлайн кинотеатра (60 тысяч пользователей, два года жизни), а дальше по этим данным делается полный цикл аналитики: SQL, метрики, выживаемость, сегменты, модель оттока, A/B тест, uplift, difference in differences, прогноз, аномалии, отчет и Excel.


Результат работы: `results/report.html` (отчет на русском, 12 разделов, 31 график), `results/cinema_report.xlsx` (13 листов, формулы пересчитаны) и 17 таблиц в `results/tables`.

## Содержание

| Блок | Что сделано | Где |
|---|---|---|
| Данные | симулятор с общими случайными числами: для каждого человека известен исход «с оффером» и «без», «с повышением цены» и «без» | `src/cinema/sim.py`, `world.py`, `gen.py` |
| Качество данных | 7 проверок, в данные подложены 6 видов ошибок, все найдены в точности | `sql/01_quality.sql`, `sql/02_views.sql` |
| SQL | представления, оконные функции, рекурсивный CTE, снимок user_month, водопад MRR, когорты, воронка и CAC | `sql/` |
| Метрики | MRR (новые, возвраты, рост тарифа, цена, сжатие, уходы), NRR, GRR, quick ratio, когорты, LTV и окупаемость каналов | `metrics.py` |
| Выживаемость | Каплан Майер с интервалом Гринвуда, лог ранг тест, дискретная модель риска на данных «человек-неделя» (логистическая регрессия на IRLS, написана руками) | `survival.py` |
| Сегменты | KMeans по поведению, выбор числа кластеров, сверка с заложенными типами (ARI) | `segments.py` |
| Модель оттока | временное разбиение, логрегрессия и бустинг, калибровка, кривая прибыли, абляция признаков, демонстрация утечки | `churn.py` |
| Эксперимент | проверка SRM, ITT, бутстреп и перестановочный тест, регрессионная поправка, мощность, подгруппы | `experiments.py` |
| Uplift | T-learner, кривые Qini, оценка политики против настоящих эффектов из симулятора | `experiments.py` |
| Причинность | difference in differences с блочным бутстрепом, event study, плацебо | `experiments.py` |
| Прогноз | Хольт Винтерс (руками), регрессия на календаре, скользящая проверка, интервалы по ошибкам прошлых прогнозов | `forecast.py` |
| Аномалии | биномиальный тест с поправкой Бенджамини Хохберга, CUSUM, изоляционный лес, робастный z счет | `anomaly.py` |
| Отчет | Jinja2, все числа в тексте подставляются из расчета, а не пишутся руками | `report.py`, `report/template.html.j2` |
| Excel | 13 листов, часть ячеек с живыми формулами | `excel_export.py` |
| Тесты | 41 тест (алгоритмы против scipy и sklearn, SQL тождества, защита от утечек, сквозной прогон) | `tests/` |

## Как запустить

Нужен Python 3.11 или новее. На Windows лучше работать в PowerShell или WSL.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows PowerShell; в Linux и WSL: source .venv/bin/activate
pip install -r requirements.txt

python run_all.py               # полный прогон на 60 000 пользователях, около двух минут
python run_all.py --users 20000 --seed 7 --regen --out results_small    # быстрый прогон на меньшем мире
```

Первый запуск сам сгенерирует базу `data/cinema.db` (около 95 МБ, в архив она не входит). Потом откройте `results/report.html` в браузере.

Тесты:

```bash
pytest
```

## Что получилось (60 000 пользователей, seed 42)

- MRR на конец данных 8,13 млн ₽, 15 437 платящих подписчиков, годовой NRR 53%.
- Удержание: через 3 месяца 77%, через 6 месяцев 66%, через 12 месяцев 48%.
- Все 6 подложенных проблем качества данных найдены в точности (634 дубля, 40 нулевых платежей и так далее).
- Модель оттока: AUC 0,833 на отложенном периоде, верхние 10% по риску ловят 59% уходов. Простое правило «часы упали» дает 0,806, и это тоже вывод отчета.
- A/B оффер: оценка эффекта -6,8 п.п. при заложенных -6,9 п.п.
- Повышение цены: DiD дает +0,24 п.п. недельного оттока при заложенных +0,33 п.п., а наивное сравнение до и после даже не показывает эффекта (+0,02 п.п.), потому что мешает сезонность.
- Сбой платежного шлюза: биномиальный тест нашел все три дня без ложных тревог.
- Прогноз регистраций на 28 дней: ошибка WAPE 10,6% против 15,3% у наивного «как неделю назад».

## Недостатки

- **Данные синтетические.** Выводы про каналы и сегменты нельзя переносить на настоящий сервис, важна только методика.
- **Сверка с правдой: 19 из 23.** Четыре интервала не накрыли заложенное значение (риск для referral, tv, web и вовлеченности). Причина найдена и проверена: модель риска смешивает уход и возвращение после спада интереса, а заложенные коэффициенты относятся к «чистому» риску. Диагностика с группой lost_cause, у которой возврата нет, подтверждает это. Таблица лежит в разделе 11 отчета и на листе «Сверка с правдой».
- **Uplift на этой выборке не работает.** На 1 437 людях разница с случайным выбором внутри шума. Это показано в отчете, а не скрыто.
- **Утечка в случайном разбиении здесь мала** (AUC 0,837 против 0,833 по времени), потому что в симуляции нет сильных личных эффектов. На реальных данных разница обычно больше. Утечка из будущего, наоборот, дает 0,986, и это показано отдельно.
- Выручка каналов это выручка, а не прибыль: нет маржи и стоимости контента.
- DiD опирается на допущение параллельных трендов. Плацебо его поддерживает, но доказать допущение нельзя.
- Никаких внешних библиотек для статистики (statsmodels, lifelines) не использовано специально, алгоритмы написаны руками и сверены с scipy и sklearn в тестах.
